## Introduction
{:#introduction}

For many years now,
Linked Data on the Web has existed in many shapes and forms.
This variety allows the [RDF data model](cite:cites spec:rdf) underpinning the semantic web to be used across many environments, covering various use cases.
Besides a heterogeneity in data,
the Linked Data ecosystem also knows many differing processors to query data from one or many sources.
The modular query engine, [Comunica](cite:cites comunica), was introduced to unionize querying over the different shapes and forms of RDF data, while supporting many data processing techniques.    
Even though Comunica's modular architecture has proven fruitful,
enabling a _sustainable_ maintenance of a [SPARQL 1.1](cite:cites spec:sparqllang) query engine supporting many RDF datasets and query processing techniques,
it was limited to processing basic SPARQL 1.1 queries and, though a conversion step a [subset of GraphQL](TODO: sparql-graphql paper RT).

This limitation was not arbitrary, but technical.
The parsing and generating software on which Comunica relied to transform a SPARQL string to and from SPARQL algebra was a big monolith.
Modifications to the monolith would thus entail that either:
1. Comunica maintains its own fork of the original project,
2. the Comunica developers submit changes to their parsing software package thereby changing its behavior beyond SPARQL 1.1, or
3. the Comunica developers submit changes to their parsing software package and maintain backward compatibility by introducing many conditionals, thereby complicating that package's maintainability.

the newly created [Traqula parsing generating and transformations framework](TODO: traqula)
created the opportunity for Comunica to modularize its parsing and generating software.
